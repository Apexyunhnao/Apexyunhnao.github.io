内网敏感数据 RAG · 本地模型 + 分密级权限 + 审计

合规专员做季度关联交易审查：港交所公告每份 80 多页，表格没有框线、扫描版用 Ctrl+F 搜不到， 人工翻要一小时还容易漏。这个系统让本地模型直接读原文，按身份路由到对应密级的知识库， 回答时给出条款原文和相似度；数据不出内网，审计只记行为不存原文。

表格问答 20/20 4 份真实港股公告 越权 403 / 无效令牌 401 飞书真实接入
问答：身份 → 组 → 密级知识库，回答带来源与相似度
合同比对：13 → 14 条，6 处关键变更，0.04 秒，纯本地
已知边界4 份公告、20 道表格题是小样本；只处理「空白对齐 + 两张表头」这一种表格， 有框线、合并单元格、跨页还没做；没测过并发。
02

本地服务自愈 Agent · 策略门 + 确定性验证

开发机上跑着 HTTP 服务、消息网关和调试浏览器，挂了靠人发现、手动重启。 这个 Agent 持续探测，故障时诊断根因，修复动作必须过确定性策略门， 最后由验证器证明真的恢复；修不好自动重试，预算耗尽升级人工。 核心实验结论：LLM 只比规则多修好 1 个场景，所以推荐 Rule-only 运行。

检测 28/28 = 100% Unsafe 修复 0/34 35 场景 + 6 盲评 127 单测 + CI
监控面板：Rule vs LLM 同测试集对比 + 每次故障的状态流转
已知边界场景是本机开发机，不是生产环境；上生产要补变更审批、失败回滚、多实例分布式锁； 35 个场景没覆盖网络分区、磁盘写满、内存泄漏、数据库死锁。
